# How To Serve Flask Applications with uWSGI and Nginx on Ubuntu

!!! Note

    The following content is based on the [How To Serve Flask Applications with uWSGI and Nginx on Ubuntu 22.04](https://www.digitalocean.com/community/tutorials/how-to-serve-flask-applications-with-uwsgi-and-nginx-on-ubuntu-22-04).

## Flask

### Project Structure

``` bash
sammy@ip-172-31-45-111:~/myproject$ ls -al
total 28

drwxrwxr-x 5 sammy sammy    4096 Sep  1 01:17 myprojectenv
-rw-rw-r-- 1 sammy sammy      68 Sep  1 01:47 wsgi.py
```

- `myprojectenv`: the project's virtual environment
- `myproject.py`: sample app
- `wsgi.py`: the WSGI entry point
- `myproject.ini`: WSGI configuration file
- `myproject.sock`: generated by `sudo systemctl start myproject`. When you run `sudo systemctl stop myproject`, the application removes the `.sock` file.

### Sample App

``` bash title="~/myproject/myproject.py"
from flask import Flask
app = Flask(__name__)

@app.route("/")
def hello():
    return "<h1 style='color:blue'>Hello There!</h1>"

if __name__ == "__main__":
    app.run(host='0.0.0.0')
```

## uWSGI

### WSGI Entry Point

``` bash title="~/myproject/wsgi.py"
from myproject import app

if __name__ == "__main__":
    app.run()
```

### WSGI Configuration File

``` bash title="~/myproject/myproject.ini"
[uwsgi]
module = wsgi:app

master = true
processes = 5

socket = myproject.sock
chmod-socket = 660
vacuum = true

die-on-term = true
```

### Systemd Unit File

Creating a systemd unit file will allow Ubuntu's init system to automatically start uWSGI and serve the Flask application whenever the server boots.

``` bash title="/etc/systemd/system/myproject.service"
[Unit]
Description=uWSGI instance to serve myproject
After=network.target

[Service]
User=sammy
Group=www-data
WorkingDirectory=/home/sammy/myproject
Environment="PATH=/home/sammy/myproject/myprojectenv/bin"
ExecStart=/home/sammy/myproject/myprojectenv/bin/uwsgi --ini myproject.ini

[Install]
WantedBy=multi-user.target
```

## Nginx

Configure Nginx to pass web requests to the `myproject.sock` socket using the `uwsgi` protocol.

### Create a new server block

``` bash title="/etc/nginx/sites-available/myproject"
server {
    listen 80;
    server_name your_domain www.your_domain;

    location / {
        include uwsgi_params;
        uwsgi_pass unix:/home/sammy/myproject/myproject.sock;
    }
}
```

### Enable the server block

``` bash
sudo ln -s /etc/nginx/sites-available/myproject /etc/nginx/sites-enabled
```

### Test for syntax erros

``` bash
sudo nginx -t
```

### Restart the Nginx process

``` bash
sudo systemctl restart nginx
```

## Adding SQLite & Serving REST API Endpoints

Python includes native support for SQLite via its standard library `sqlite3` module. Here is how to initialize a database, expose JSON API endpoints in Flask, and configure permissions for uWSGI.

### 1. Install SQLite CLI Tool (Ubuntu)

```bash
sudo apt update
sudo apt install sqlite3 -y
```

### 2. Create the Database Schema & Init Script

Navigate to your project directory:

```bash
cd ~/myproject
```

#### Schema Definition (`schema.sql`):

```sql title="~/myproject/schema.sql"
DROP TABLE IF EXISTS items;

CREATE TABLE items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    description TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Initial seed data
INSERT INTO items (name, description) VALUES 
('First Item', 'Created during database initialization'),
('Second Item', 'Another test item for API');
```

#### Initialization Script (`init_db.py`):

```python title="~/myproject/init_db.py"
import sqlite3

connection = sqlite3.connect('database.db')

with open('schema.sql') as f:
    connection.executescript(f.read())

connection.commit()
connection.close()

print("Database initialized successfully!")
```

Run the initialization script using your project's virtual environment:

```bash
~/myproject/myprojectenv/bin/python init_db.py
```

### 3. Update Flask Application with API Endpoints (`myproject.py`)

Update `myproject.py` to manage database connections with Flask application context (`g`) and serve `GET` and `POST` API routes:

```python title="~/myproject/myproject.py"
import os
import sqlite3
from flask import Flask, g, jsonify, request

app = Flask(__name__)

# Absolute path to database file
DB_PATH = os.path.join(os.path.dirname(__file__), 'database.db')

def get_db():
    db = getattr(g, '_database', None)
    if db is None:
        db = g._database = sqlite3.connect(DB_PATH)
        # Enable column access by name (dict-like rows)
        db.row_factory = sqlite3.Row
    return db

@app.teardown_appcontext
def close_connection(exception):
    db = getattr(g, '_database', None)
    if db is not None:
        db.close()

@app.route("/")
def home():
    return "<h1 style='color:blue'>Flask + SQLite App is Running!</h1>"

# GET: Fetch all items
@app.route("/api/items", methods=["GET"])
def get_items():
    db = get_db()
    cursor = db.execute("SELECT id, name, description, created_at FROM items ORDER BY id DESC")
    items = [dict(row) for row in cursor.fetchall()]
    return jsonify(items), 200

# POST: Create a new item
@app.route("/api/items", methods=["POST"])
def create_item():
    data = request.get_json()
    if not data or "name" not in data:
        return jsonify({"error": "The 'name' field is required"}), 400

    name = data["name"]
    description = data.get("description", "")

    db = get_db()
    cursor = db.execute(
        "INSERT INTO items (name, description) VALUES (?, ?)",
        (name, description)
    )
    db.commit()

    return jsonify({
        "id": cursor.lastrowid,
        "name": name,
        "description": description,
        "message": "Item created successfully"
    }), 201

if __name__ == "__main__":
    app.run(host='0.0.0.0')
```

### 4. Configure File and Directory Permissions

!!! warning "SQLite Write Lock Permissions"
    SQLite requires **Write permission** on both the `database.db` file and the **parent directory (`~/myproject`)** to create temporary journal/lock files (`database.db-wal` / `database.db-journal`) during `INSERT`/`UPDATE` operations.

Ensure the `www-data` group has read and write permissions:

```bash
# Set ownership and group permissions on the database file
sudo chown sammy:www-data /home/sammy/myproject/database.db
chmod 664 /home/sammy/myproject/database.db

# Ensure the parent directory is writable by group
chmod 775 /home/sammy/myproject
```
